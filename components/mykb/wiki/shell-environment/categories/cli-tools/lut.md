## Overview

LUT stands for lookup table, a precomputed mapping from input values to output values used to replace expensive or complex calculations at runtime. Instead of computing a function on every call, code indexes into an array — color grading, gamma correction, sine tables, and physics approximations all use this trick. The acronym appeared in a shell and debugging session, which fits a tool that converts or transforms values through a table defined in configuration or generated by a script.

## Color Grading

The most familiar use of LUTs is color grading: a 3D LUT maps input RGB triples to output colors, letting editors apply a consistent look across footage without recomputing color science per pixel. Formats like .cube encode these tables as text, and tools apply them by interpolating between table entries. In the shell context, a CLI might generate, inspect, or apply such a table, which explains the bash and cli tags. Interpolation matters because a finite table cannot cover every possible input; nearest-neighbor is fast but coarse, while trilinear interpolation is smoother.

## Precomputation

Beyond color, LUTs appear wherever a computation is repeated with a bounded input domain: physics simulations precompute force tables, and rendering pipelines precompute falloff curves. [[wiki/shell-environment/categories/cli-tools/density|density]] and [[wiki/shell-environment/categories/cli-tools/rng|RNG]] tables in the simulation cluster are sibling examples. The trade-off is memory versus speed, and correctness hinges on the table's resolution and interpolation method — a coarse table introduces visible banding or error, which is the kind of bug that shows up in a debugging session. [[wiki/shell-environment/categories/cli-tools/fluid-simulator|fluid simulator]] shows a domain where such tables accelerate per-timestep physics.
