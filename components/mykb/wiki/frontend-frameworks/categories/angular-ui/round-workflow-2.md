## Overview

A round workflow is an iterative way of working in which the same cycle — plan, act, review — repeats until a stopping condition is met. The two sessions that reference it cut across API, frontend, mobile, and shell work, which fits a general pattern: each round produces a reviewable increment, and feedback from the round shapes the next one.

## Round Structure

- A round starts with a goal and a bounded set of tasks; the scope is sized so progress is visible at the end.
- Each round ends with a check: tests, builds, or demos that verify the increment before the next round begins.
- Unfinished work is carried forward explicitly rather than silently dropped.
- Retrospective notes from each round feed the next plan, so lessons are captured while they are fresh.

## Why It Matters

- Round-based iteration keeps long-running work observable and reduces the blast radius of mistakes.
- The tags suggest rounds were applied to UI work (angular, dom), API integration (api, auth), and shell automation (bash, cli) alike.
- Pairing rounds with checkpoints makes state easy to reconstruct, which is valuable when sessions are resumed later.
- A round can also be a unit of review: small, frequent reviews catch drift earlier than one large review at the end.
