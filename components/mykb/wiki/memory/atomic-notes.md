# Atomic Notes

## Summary
An atomic note holds a single idea, claim, or question — nothing more. Atomicity makes notes uniquely addressable and linkable, so many larger documents can reuse the same small note without duplication. It is the size rule underneath every other note-taking practice that claims to build a network.

## Details
- **Rule of one** — one note, one idea; split a long page into several atomic notes when topics diverge. If a note's title has to be a compound sentence, it is already two notes. The rule is not about word count — a note can be long if it is still about one thing — but about focus.
- **Payoff** — links are precise, deduplication is easy, and syntheses compose atomic notes like building blocks. A note titled "Backlinks" can be linked from a dozen places; a note titled "Backlinks and graph notes and Obsidian" forces every linker to discuss all three or none.
- **Naming** — the title should be a noun phrase that names the idea ("Retrieval Practice") rather than a file location or a sentence fragment. Stable, descriptive titles keep wikilinks valid as the note grows, because links target titles, not content.
- **Agent relevance** — mykb's concept pages are atomic units; entity extraction from sessions produces atomic candidates automatically. When a session's output mentions several distinct claims, the curation loop should emit several atomic pages instead of one sprawling digest, so later retrieval can cite precisely.
- **Failure modes** — atomicity taken to the extreme fragments a topic across dozens of near-empty notes that are hard to discover; merging and renaming then breaks links. The counter-discipline is the evergreen practice of revising titles and consolidating duplicates during review.
- **Tradeoffs** — atomic notes cost more overhead per idea (files, titles, links) than a single journal page, but they pay back in reuse and precise linking; the overhead is only worth it when notes are actually linked and revisited.
- **RSIS3/mykb relevance** — atomicity simplifies deduplication: when the L1 loop captures overlapping facts, exact-topic matching on atomic pages prevents the knowledge base from growing duplicate nodes.
