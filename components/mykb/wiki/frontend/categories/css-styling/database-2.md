## Overview

Database 2 is an entity page for structured data storage systems as they appear across the Cosmos session corpus. The sessions grouped under this name cover relational and NoSQL patterns, including schema design, migration scripts, and query optimization. The related technologies — api, auth, bootstrap, bug, cli, css, database — indicate that database work in the sessions was rarely isolated: it showed up while building API endpoints, debugging state, scripting migrations, and styling the interfaces that present the data.

Schema design is the first discipline. Relational work starts with tables, keys, and constraints; NoSQL work starts with the query shapes the application needs. Migrations then evolve the schema safely, using versioned scripts that apply forward changes and, where possible, roll back. Query optimization is the third pillar: indexes, execution plans, and measured latency replace guesswork about why a request is slow.

## Key Properties

- Relational patterns: schemas, normalization, joins, and transactions.
- NoSQL patterns: denormalized documents, key-value access, and flexible schemas.
- Migrations: versioned, idempotent scripts applied in order.
- Optimization: indexes, query plans, and profiling to close the loop.
