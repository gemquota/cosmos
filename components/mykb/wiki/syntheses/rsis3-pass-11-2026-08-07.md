# RSIS3 Pass 11 — Ops + Capstone

## Summary
Pass 11 closed the integration arc with ops automation and the capstone
proof. The deploy path is now **CI auto-sync**: `.github/workflows/deploy.yml`
mirrors `main` into `gh-pages` on every push (plus a daily safety net), and
`infra/deploy/sync-gh-pages.sh` encodes the old manual §6 procedure. Loops
run **on schedule without babysitting**: `.github/workflows/loops.yml` runs
the full L1–L9 batch nightly (and on demand) via `infra/loops/run-batch.sh`,
commits telemetry + snapshots back to `main`, and deploys. Monitoring is a
two-layer net: the local `infra/heartbeat` (extended to URL watches — the
live GitHub Pages site) plus an hourly `.github/workflows/health.yml` running
`infra/health/check.sh` (live site 200, snapshots `--check`, contracts, wiki
links, practices). The **capstone run** then proved the whole chain in one
batch: cycle 1 sourced its L2 goal from a SPACE spec artifact (`run --goal
from-space` → telemetry `l2_start` referencing `spec artifact
abstraction_level`), L3 self-wrote syntheses cycles 11–15 via the MyKB
gateway, and the regenerated Guide payload surfaces the spec trace + newest
syntheses first (dashboard reflects it).

## Details
- **Deploy auto-sync** — `infra/deploy/sync-gh-pages.sh` replaces the manual
  "checkout gh-pages; rm -rf; checkout main -- .; commit; push" ritual with
  one idempotent script (no-op when the tree is unchanged); used by CI with
  the default `GITHUB_TOKEN` (`contents: write`).
- **Scheduled loop runner** — `infra/loops/run-batch.sh` runs N full cycles
  (run/evolve/optimize/strategies/identity/metacog/metameta/mmm), keeps the
  `RSIS_DISK_USAGE_PCT` disk-pressure override, gates on `check-practices`,
  and regenerates all snapshots. CI runs it nightly with cycle 1 spec-sourced.
  `GITHUB_TOKEN` pushes don't retrigger workflows, so loops.yml deploys
  explicitly after committing.
- **Monitoring** — `infra/heartbeat/heartbeat.mjs` gained URL watches
  (default HTTP 200 check) so the live site is monitored alongside local
  ports; `watches.json` now covers dashboard :9000, meta viewer :8899, web
  UI :8888, mykb daemon :8765, and the deployed site. `infra/health/check.sh`
  is the CI gate (site 200, `gen-static-data --check`, contracts, link
  check, practices) run hourly by health.yml — failures alert via workflow
  status.
- **Capstone batch** — 5 cycles × 8 loops = 40 executions, cycle 1
  `run --goal from-space`. Telemetry went +5 per loop (L1=31, L2=31, L3=29,
  L4=29, L5=33, L6=30, L7=28, L8=28, L9=28; 222 files / 724 events / 0
  malformed); L3 self-wrote `rsis3-l3-cycle-{11..15}-…2026-08-07.md` +
  `log.md` entries; graph grew to 5,424 nodes / 36,913 edges.
- **Chain proof** — the capstone `l2_start` goal references `spec artifact
  abstraction_level` (series 1, Q1.1.1) at 04:46Z; the Guide's
  `live.telemetry.spec_traces` lists it first, and
  `live.memory.syntheses` lists the five new L3 syntheses first.

## Rules going forward
- Deploy is a scripted, idempotent sync (`main` → `gh-pages`); never hand-
  rebuild the pages branch.
- Scheduled loop runs keep the disk override, gate on `check-practices`, and
  regenerate snapshots in the same script — one entry point, one CI job.
- Any new service gets a heartbeat watch (port or URL); the live site is a
  first-class watch target.
- Batch scripts must run repo-root commands from the repo root (`cd "$DIR"`)
  — subshells for component dirs don't move the parent cwd.
- Capstone cadence: every ops pass re-proves spec → goal → cycle → MyKB →
  dashboard with one spec-sourced cycle.
