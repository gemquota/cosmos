# Wiki Stats Hub Architecture & Snapshot Hygiene

## Context

Added a stats hub (`stats.html`) for the MyKB wiki, generated by
`.wiki-daemon/build_stats.py`, and wired it into the unified dashboard's
MyKB tab. Also fixed a stale-snapshot drift that had made `files.json` (2824)
out of sync with the git-tracked wiki (2825 md files). Rules here are the
durable conclusions.

## Patterns

1. **One generator script, embedded JSON, one artifact.** `build_stats.py`
   walks the wiki once, computes all metrics (frontmatter/body word counts,
   wikilinks, areas, tags, per-month additions, graph degrees), and writes a
   self-contained `stats.html` with the dataset embedded as JSON. No runtime
   data fetching — the page works offline and from any static host.

2. **Graceful degradation is a first-class requirement.** Stats tiles and the
   per-chart data tables render from the embedded JSON even when Chart.js
   fails to load (offline / blocked CDN). Charts are drawn only after a
   successful script load; a banner states the data caveats (word counts
   exclude frontmatter and code fences, `log.md` is an outlier, stubs are
   low-content). Never let the visualization layer take the data layer down.

3. **Snapshot hygiene is a fixed pipeline, not a chore.** After any wiki
   change the regeneration order is: `build_graph.py` (graph.json) →
   `gen-static-data.py` (files.json/ecosystem.json) → `gen-static-data.py
   --check` (must exit 0). A files.json that lags the tree is a deployment
   hazard: the wiki browser and stats hub read it, so commit it atomically
   with the notes it describes.

4. **Deploys are full-tree mirrors.** The live site is the `gh-pages` branch,
   which is an unrelated-history mirror of `main` (empty merge-base, full-tree
   deploy commits). Deploy by re-materializing the `main` tree onto
   `gh-pages` and committing — never by cherry-picking single files, or
   partial copies will silently shadow newer wiki content.

## Consequences

- Stats hub answers "how big is the wiki" without server-side computation:
  2,825 md files, threshold counts (300+/400+/500+ words), longest notes,
  status/area/tag distributions, and activity over time.
- Keeping `graph.json`, `files.json`, and `stats.html` generated from the
  same tree prevents the three consumers (graph, browser, stats) from
  disagreeing about the wiki's contents.
