# RSIS3 Pass 7 — Ecosystem Data Contracts

## Summary
Pass 7 (contract-first) made the inter-component data shapes explicit and
machine-checked. Every shared shape the ecosystem emits — OKF frontmatter,
`files.json`, `ecosystem.json`, `loops.json`, telemetry JSONL, and the SPACE
framework definition — now has one documented contract
(`contracts/README.md`) enforced by a stdlib-only validator
(`contracts/validate.py`). The validator is wired into both gates:
`gen-static-data.py --check` (deploy/CI) and `python -m rsis
check-practices` (loop pipeline, telemetry shape). The full 5-cycle × L1–L9
batch ran with **+5 net starts per loop, 0 errors**; the telemetry contract
now parses all 359 events across 100 files with zero malformed.

## Details
- **Contracts, not conventions** — six sections in `contracts/README.md`
  define field-level rules: OKF frontmatter types and required keys,
  `files.json` path/title/tags invariants, `ecosystem.json` telemetry
  arithmetic (`passed+failed+held == total`), `loops.json` ten-loop shape
  (L0–L9 ids + required keys + status vocabulary), telemetry JSONL event
  grammar (snake_case `type`, ISO-8601 `timestamp`, loop events
  `l{1..9}_*`, workspace events like `tool_call` allowed), and the SPACE
  framework definition (series totals must sum to meta totals — 67
  open-ended + 259 multi-choice = 326 probes).
- **One validator, two gates** — `contracts/validate.py` is importable by
  `gen-static-data.py --check`, and `check-practices` gained
  `check_telemetry_contract`, a self-contained mirror of section 5 so the
  nested rsis3 repo stays deployable on its own. Divergence risk is
  documented in both places.
- **Freshness vs shape** — `gen-static-data --check` now separates contract
  FAILs (shape violations) from snapshot staleness (committed `files.json`
  older than the git-tracked tree). Staleness is routine drift fixed by
  regeneration; a contract FAIL is real breakage. Pass 7 caught live
  staleness: the pass-6 synthesis was committed without being snapshotted.
- **Disk override semantics** — `RSIS_DISK_USAGE_PCT` replaces the *limit*,
  not the measured value. With the disk at 99.6–100%, `run` (L1/L2) is
  blocked at any limit below ~99.6 while the tuner loops still execute —
  set the override to 100 for deterministic batches on a full device.
  A batch started with the wrong override is safely abortable: telemetry
  stays well-formed and the partial cycle simply adds +1 to the middle
  loops (L3–L8).
- **OKF reality check** — all 5,405 wiki pages carry frontmatter;
  `type`/`title` are universally present, but `status` (534),
  `description` (124), `tags` (118), and `timestamp` (119) are missing on
  legacy pages → WARN, not FAIL, so the gate stays honest without blocking.

## Rules going forward
- A new shared data product gets a `contracts/README.md` section and a
  validator function before passes build on it.
- Shape violations fail the gate; snapshot drift is fixed by
  `python3 gen-static-data.py` + `--check`, never by editing snapshots.
- Run batches on full disks with `RSIS_DISK_USAGE_PCT=100`; keep the
  telemetry contract in sync in both `contracts/validate.py` and
  `rsis/practices.py`.
