# RSIS3 Pass 8 — MyKB Memory Link

## Summary
Pass 8 (memory link) closed the loop between RSIS3 and MyKB in both
directions. A stdlib-only `MyKBGateway` (`components/rsis3/rsis/mykb_gateway.py`)
lets loops **read** OKF syntheses for context — L2 can source its goal from
MyKB (`python -m rsis run --goal from-mykb`) and L3 picks related notes for
its synthesis links — and lets L3 **write** its own durable memory: every
evolution cycle now produces a well-formed OKF synthesis in
`wiki/syntheses/` plus a dated `log.md` entry, instead of waiting for a
human post-processing step. The full 5-cycle × L1–L9 batch ran **+5 net
starts per loop, 0 errors**, and each of the 5 L3 cycles left a durable
synthesis visible in the wiki and the knowledge graph.

## Details
- **One gateway, both directions** — `MyKBGateway` resolves its root from
  `RSIS_MYKB_PATH`, else `<workspace>/../mykb` (rsis3 → mykb sibling);
  `read_syntheses`/`search_syntheses` parse OKF frontmatter with a
  token-overlap ranker (stdlib-only, mirrors the wiki daemon's parser), and
  `write_synthesis`/`append_log` emit OKF notes and prepend bundle-log
  blocks. Writes are failure-isolated: a MyKB error logs + records
  `l3_mykb_error` telemetry and never fails the evolution cycle.
- **L3 is now self-consolidating** — phase 5 of `loop_l3.py` writes
  `rsis3-l3-cycle-<n>-cross-session-memory-consolidation-2026-08-06.md`
  (type/title/description/tags/timestamp/status frontmatter, insights /
  strategies / redundancies / trends summary, predecessor link chain) and a
  `## YYYY-MM-DD` entry in `components/mykb/log.md`. Telemetry records
  `l3_mykb_write` per cycle.
- **Loop context** — `main.py` gained `_resolve_goal`: `--goal from-mykb`
  (for `run` and `drive`) sources the improvement goal from the most
  relevant synthesis and embeds the synthesis path in the goal string for
  traceability.
- **Cycle ordinals, not process counters** — each `evolve` invocation is a
  fresh process, so the in-process cycle counter resets; the title sequence
  is derived from the durable count of existing `rsis3-l3-cycle-*`
  syntheses. Separate invocations now get distinct, stable titles
  (`cycle 1 … cycle 5` in the pass-8 batch) instead of colliding on one
  slug. (First batch wrote 5 identically-titled suffixed notes; fixed in
  code and artifacts before this synthesis.)
- **Batch** — 40 executions (5 × `run`, 5 × each one-shot loop), +5 net
  starts per loop, 0 errors. Telemetry now L1=21, L2=21, L3=19, L4=19,
  L5=23, L6=20, L7=18, L8=18, L9=17; ledger 140 files / 482 events / 0
  malformed.

## Rules going forward
- Memory writes belong in the loop pipeline: L3 consolidation is
  self-writing (synthesis + log), not a manual ritual; humans only do the
  pass-level index/count update and snapshot regen.
- A memory hiccup degrades to a warning — never fail an evolution cycle on
  MyKB write errors.
- New loop-generated artifacts must use durable sequence numbers (not
  per-process counters) for stable, collision-free titles.
- Keep the OKF shape (type/title required; description/tags/timestamp/
  status optional-but-encouraged) so gateway output passes the contract
  gate unchanged.
