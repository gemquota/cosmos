## Overview

The Hard Problem, in the philosophy-of-mind sense associated with David Chalmers, asks why physical information processing gives rise to subjective experience (qualia). It is contrasted with the "easy problems" of explaining cognitive functions — discrimination, integration, reportability — which are tractable in principle. The term surfaces in sessions about ORM/data tools, likely because agent architecture discussions borrow this vocabulary when asking whether a system's internal representations amount to more than their functional behavior.

## Relevance to Agent and AI Systems

- The easy problems map onto measurable capabilities: perception, memory, reasoning, and self-report.
- The hard problem is not currently a testable engineering property; no objective benchmark distinguishes a system with inner experience from one without.
- Designers instead rely on observable proxies: introspection-like logs, uncertainty estimates, and metacognitive monitoring.
- Treating "consciousness" as an implementation detail to be engineered is speculative; the practical stance is to focus on behavior, traceability, and safety.

## Documentation and Model Notes

- When these terms appear in data-tooling sessions, they usually frame questions about what an ORM's object model represents versus what the system actually experiences.
- Prefer operational definitions: describe what the tool does, what it observes, and what it can verify, rather than claiming inner states.
- The easy/hard distinction is a useful rhetorical tool for scoping work and avoiding unfalsifiable claims in agent evaluation.
