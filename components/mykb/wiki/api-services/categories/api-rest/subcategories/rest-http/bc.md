## Bc

BC — Backward Compatibility or Before Christ. Referenced in technical discussions.

In technical discussions, BC most often means backward compatibility: the property that a newer version of a system, library, or API continues to work with clients and data built for an older version. Maintaining backward compatibility is a core discipline in API design, where endpoint paths, parameter names, and response shapes become contracts that consumers depend on. Breaking changes are typically gated behind version numbers, feature flags, or deprecation windows so that existing callers can migrate at their own pace.

The related topics on this page — android, api, and bash — fit the compatibility reading well. Mobile apps frequently pin API versions because older installed clients must keep working after a server upgrade, and shell scripts that parse command output break quietly when a tool changes its format. Compatibility testing, semantic versioning, and careful deprecation notices are the standard defenses.

There is also a literal `bc` command in Unix-like systems: an arbitrary-precision calculator language commonly used inside shell scripts for floating-point arithmetic, invoked as `echo "scale=2; 10/3" | bc`. This reading is plausible given the bash tag, though the session does not disambiguate. Finally, BC can simply mean "before Christ" in date contexts.
