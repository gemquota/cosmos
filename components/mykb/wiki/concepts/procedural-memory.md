# Procedural Memory

## Summary
Procedural memory encodes how to perform tasks: sequences, tool habits, and skills that no longer need deliberation. It matters because compiled procedures are what make agents fast and consistent. For RSIS3, L2 prompt and code tuning is procedural learning.

## Details
- Differs from declarative memory: knowing how, not knowing that.
- Grows through repetition and successful execution.
- In agents: cached strategies, prompt templates, and refined tool call patterns.
- Open questions: how to version and review learned procedures safely.
- Procedural memory stores how to do things — skills and routines — acquired through practice and expressed as performance rather than facts.
- It is the memory system behind riding a bike, touch-typing, and following a well-learned workflow without conscious recall.
- Procedural knowledge is hard to verbalize, which is why documenting it requires task analysis and worked examples.
- In agents, procedural memory maps to the executable workflows and scripts that encode how curation and acquisition are done.
- **Worked example / comparison** — Worked example — the wiki's promotion workflow is procedural memory: after enough passes, the checklist runs smoothly as a routine, but the written procedure is what makes it teachable.
- For mykb, procedural memory is documented as the skill layer, complementing episodic and semantic memory in the memory cluster.
