# Declarative Memory

## Summary
Declarative memory covers facts (semantic) and events (episodic) that can be explicitly stated and queried. It matters because it is the shareable, inspectable part of an agent's knowledge. The mykb wiki is built almost entirely from declarative memory.

## Details
- Subdivided into semantic and episodic memory.
- Explicitly inspectable: readable, editable, linkable as markdown.
- Contrast with procedural memory, which is know-how.
- Open questions: which facts deserve storage versus recomputation.
- Declarative memory is the memory system for facts and events that can be consciously recalled and stated — episodic plus semantic memory.
- It contrasts with procedural memory: declarative is 'knowing that', procedural is 'knowing how'.
- Declarative memory is what tests probe when they ask you to recall or recognize facts, and it is the type most affected by sleep and consolidation.
- For a knowledge system, declarative memory is the article-and-fact layer, while procedural memory is the workflow layer.
- **Worked example / comparison** — Worked example — knowing that exponential backoff doubles delays is declarative; running a retry fix without thinking is procedural; the wiki documents both.
- For mykb, declarative memory is the umbrella concept covering episodic-memory and semantic-memory.
