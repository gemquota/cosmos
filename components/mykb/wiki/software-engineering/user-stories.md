# User Stories

## Summary
A user story is a short, plain-language statement of a user need — 'As a reader, I want search, so I can find articles fast'. Stories capture intent for planning, with details deferred to acceptance criteria and conversation.

## Details
- The template (role, want, benefit) keeps stories user-centered and value-focused.
- Stories are promises to talk, not complete specifications: details live in acceptance criteria.
- INVEST helps: Independent, Negotiable, Valuable, Estimable, Small, Testable.
- Splitting big stories into slices keeps them shippable and estimable.
- Stories belong to the backlog; epics are big stories to be split.
- For the mykb bundle, stories describe reader and curator needs: search, link verification, and source tracking.
- Worked example — 'As a curator, I want a batch link-check report, so I can fix broken sources before publication' — with acceptance criteria for the report's contents.
