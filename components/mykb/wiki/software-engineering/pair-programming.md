# Pair Programming

## Summary
Pair programming has two developers share one task: the driver writes code while the navigator reviews and plans in real time. It trades throughput for continuous review, knowledge sharing, and fewer defects.

## Details
- Roles should switch regularly to keep both people engaged and share expertise.
- It is most valuable on complex or unfamiliar work; trivial tasks waste the pair.
- RSIS3 relevance: human-in-the-loop review of agent output is a form of pairing.
