## Overview

DS is an overloaded abbreviation: in algorithm-heavy work it means data structures, and in analytics work it means data science. Both readings appear in technical sessions, and the intended meaning depends on context. The shared theme is organizing and extracting value from data — one reading emphasizes how data is stored and manipulated, the other emphasizes how it is analyzed and modeled.

## Data Structure Angle

- Arrays, lists, maps, trees, and graphs each offer different trade-offs for access, insertion, and search.
- Choosing the right structure determines whether an operation runs in constant, logarithmic, or linear time.
- Understanding asymptotic growth is what turns a working solution into one that survives real data sizes.

## Data Science Angle

- Workflows span collection, cleaning, feature engineering, model training, and evaluation.
- Notebooks and dashboards support exploratory analysis and communication of results.

## Context in Sessions

- Technical sessions use the abbreviation in both senses, so readers must infer from the surrounding code whether algorithms or analytics are the subject.
- When DS refers to data structures, expect discussion of complexity, containers, and traversal; when it refers to data science, expect pipelines, statistics, and modeling.
- The shared thread is data: how it is organized, transformed, and interpreted.
- When both readings could apply, the deciding cues are usually tooling names (libraries, runtimes) and the shape of the data being discussed.
