subcategories, and a consolidation proposal for conceptually near-identical
graphs. Diagrams are grouped by primary cognitive job, then subcategorised by
encoding technique.

## 3 · Consolidation proposal

### Strong merge (conceptually near-identical)

1. **B-04 Self-Improvement Cycle ⊕ B-07 Improvement Flywheel**
   Both render the same recursive loop (ideate → execute → evaluate →
   consolidate). B-07 only adds "strategize" and a compounding annotation.
   → Merge into a single **"Recursive Improvement Cycle"**: keep B-04's
   L1→L2→L3 detail, fold in B-07's 5th stage and momentum note. Net −1 card.

2. **B-03 Component Relationships ⊕ O-01 Relationship Diagram**
   O-01 is the strict superset (all six flows + endpoints + external actors +
   shared filesystem). B-03 is only useful as a Basic-level teaser.
   → Keep B-03 only if a teaser is wanted; otherwise retire it and point Basic
   readers at O-01. Net −1 card (or −0 if teaser retained).

3. **B-06 The Cosmos Mind ⊕ A-07 The Cognition Loop**
   Same past/present/future mapping of MyKB/RSIS3/SPACE at two zoom levels
   (whole ecosystem vs single decision).
   → Merge into one **"Cosmos Cognition"** diagram with an ecosystem inset and
   a decision zoom; keep the feedback arrows. Net −1 card.

4. **B-17 Six Handoffs ⊕ A-25 Interface Contract Table** *(Round 6)*
   The same six interfaces: B-17 is the friendly cards view, A-25 adds
   transport/error-mode/cadence fine print.
   → Keep both — A-25 explicitly annotates itself as "the spec-level detail
   beneath B-17". If one must go, retire B-17 and let A-25 serve Basic. Net −1
   card only if the merge is taken.

5. **B-14 Ownership Matrix ⊕ B-22 Read/Write Ledger** *(Round 6)*
   Dual views of the same modules/stores — "who runs the code" vs "who touches
   the data".
   → Annotate each other in the legends (already done in B-22) instead of
   merging: the two questions are genuinely different. No card loss.

6. **A-22 Failure Cascade ⊕ E-15 Fault Tree** *(Round 6)*
   Same failure facts: A-22 is the mode/symptom/degraded/recovery table,
   E-15 is the OR-gate logic tree.
   → Keep both (different grammars — table vs logic) with cross-reference
   notes (already added). No card loss.

7. **A-13 Bifurcation Portrait ⊕ B-24 Integration Timeline ⊕ E-23 Evolution
   Ladder** *(Round 6)*
   Three renderings of the same λ ladder: control-parameter regimes, a
   timeline, and gated rungs.
   → Keep all three but treat them as one "λ family" with cross-links (already
   noted in each diagram's legend). No card loss.

    Same L1→L3 spine; A-01 is concrete (budgets, telemetry, governance),
    E-06 is abstract (loops about loops). → Keep both; add a note in each

11. **Cadence family — B-11 Pulse Field ⊕ B-21 Loop Roster ⊕ E-11 Coupled

    (rhythm, ratio, phase, cost). No card loss.

    E-13 is the 1D curve, X+-02 is the same concept promoted to a 2D field.

    The same whole-system plane, static vs interactive.

    interactive version adds hover/click + λ time axis. No card loss.

### Keep as-is (distinct views)

  tree, runtime map are five different "where" questions.
- **E-01 / E-02 / A-18 / A-20** — evaluator gate, telemetry pipeline, pulse
  anatomy, telemetry graph are four different "how data moves" zooms.

  write path serve different components or directions.
- **X+-03 / A-22 / E-15** — spectrum, table, and fault tree are three distinct

**Adopted in this pass:** Round 6 doubled the catalog (37 → 74 tier diagrams)
and added the Expert+ tier (12) and the interactive Ω (1). The doubling
intentionally created several near-identical families (contracts, matrices,
failures, λ ladders, clocks, entropy) — they are annotated as families with
cross-links rather than merged, because each member answers a distinct zoom or
grammar question. No cards were deleted; say the word and I'll apply any of the
strong merges above.

## 4 · Animation policy (why diagrams animate)

Animation is only used where it encodes something real:

- **E-08** — time is the 4th axis; drift = integration, growth = consolidation.
- **B-11** — pulse period = actual loop cadence (L1 seconds, RRP minutes, L3 hours).
- **A-11** — sweep = RRP dispatch order across 25 rounds / 7 series.
- **E-10** — dash flow = module maturation trajectories and relative speed.
- **B-12** — comet path = real pipeline travel (spec→implementation, lessons→consolidation, :8765 retrieval, telemetry, dashboard→SPACE launch).
- **A-13** — cursor sweep = λ advancing through the four integration regimes; loop dots spin at true cadences.
- **E-11** — ring rotation speed IS the cadence (L1 1s / RRP 12s / L3 60s), time-compressed; comets = coupling phase.
- **E-12** — comet = the live session tracing the attractor; echo = retrieval returning memory to action.

No decorative motion. Every `<animate>` has a legend line stating what it means.

**Round 5 (phase-space family):** B-12, A-12, A-13, E-11 and E-12 extend the
dynamical-systems genre from E-10 — vector fields, potential barriers, control-
parameter regimes, coupled oscillators, and a 3-state Lorenz projection — every
motion grounded in a real cadence, gate, or data path from the spec.

**Round 6 (the doubling pass):** B-13, A-24, E-18, X+-02 and the Ω page
continue the same rule:

- **B-13** — white comet circling the artifact ring = one artifact moving
  through the five states; one lap = one idea matured end-to-end.
- **A-24** — pulsing λ ring = the 4th axis (time): the memory sphere's growth
  from λ₁ to λ₄ is the integration story from A-13/B-24.
- **E-18** — comet orbiting the cost/order cycle = one artifact's journey
  through the entropy gradient; the evaluator is the energy barrier.
- **X+-02** — comet descending the entropy field = an artifact rolling from
  ideation (high entropy) to memory (low entropy), the field's gradient.
- **Ω (X++)** — no animation loop at all: motion is *user-driven*. The λ slider
  interpolates each node's keyframed position/size (memory grows, the
  dashboard fades in), and hover/tap highlights a node's neighbourhood. The
  slider is the 4th axis, and the user is the one who moves it.
